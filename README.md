> **从“她很难过”，到“她想挽留，却在说出第一句话之前收住了”。**
>
> `tudou-single-h3` 帮你把人物意图、微表情、对白和镜头放进同一条时间轴，让每一次情绪变化都有原因，也有观众能看见的过程。

## 这份 Skill 能做什么

提供剧情、人物、原始台词或参考图，获得一份可以复制使用的 **MiniMax H3 单片段完整提示词**。既支持纯文字，也支持参考图；既能写克制文戏，也能写动作、喜剧与其他题材。

| 你想控制的内容 | Skill 会怎样组织 |
| --- | --- |
| 情绪变化 | 从人物目标与触发事件出发，安排起始状态、转折和余波 |
| 对白表演 | 协调语速、音量、重音、停顿、发声准备与自然口型 |
| 双人文戏 | 同时安排说话者与听者，明确接话、迟疑或打断的节奏 |
| 微表情 | 把目光、眉眼、口唇和下颌变化放在可读的时间窗口里 |
| 人物与场景 | 保持身份、服饰、位置和环境连续，分清不同参考图的职责 |
| 镜头与动作 | 让景别、画面边界、动作幅度和镜头计划相互匹配 |
| 时间预算 | 检查台词、停顿和反应是否能装进指定时长 |
| 交付格式 | 一个 `text` 代码块，固定六段结构，方便整段复制 |

**能力边界：** 这是一套提示词编排技能。它本身不包含视频模型，不会自动上传图片、调用视频生成或消耗生成额度。实际成片由你使用的平台、模型与素材共同决定。

## 本版重点

- **听者也有戏。** 关注台词中的具体触发词，以及听者第一时间的目光、下颌或呼吸反应。
- **每句话有目的。** 试探、逼问、搪塞、安抚等行动意图，通过语气与停顿体现出来。
- **情绪连续发生。** 下一种情绪保留上一种情绪的余波，避免表情轮播和突然复位。
- **空间表达关系。** 在输入与景别允许时，用距离、朝向、视线高度和已有道具表达人物关系。
- **台词有时间可说。** 用语速和停顿估算时长，给关键反应留下空间。
- **输出格式统一。** 六个英文标题保留原样，内容可以使用中文。

```text
    └── scene-acting.md            # 听者、接话、关系、调度与时间预算
```

不要只复制 `SKILL.md`。文戏和对白编排需要读取 `references/` 中的配套文件。

### 第二步：放进 Codex 技能目录

使用默认 Codex 配置时，将整个目录放到：

| 系统 | 安装位置 |
| --- | --- |
| Windows | `%USERPROFILE%\.codex\skills\tudou-single-h3\` |
| macOS / Linux | `~/.codex/skills/tudou-single-h3/` |

如果你已自定义 `CODEX_HOME`，使用对应的 `skills/tudou-single-h3/` 目录。更新时用新版目录内容替换旧版，确认两个参考文档都已包含。

### 第三步：调用 Skill

在能够发现该技能的 Codex 对话中，输入 `$tudou-single-h3`，再描述你的片段。首次安装后如果列表尚未显示，重新打开对话或重启客户端再检查。

复制下面这段即可开始，无需提供参考图：

```text
使用 $tudou-single-h3。

写一个 6 秒、16:9、现代写实风格的视频片段。
一位穿灰色衬衫的成年女性站在室内门边，胸部以上固定近景。
她看向画面右侧一个即将离开的画外对象，想挽留，但努力保持平静。
她只说一句：“你真的要走吗？”
轻声、清晰，不哭，不微笑；说完仍看着对方，等待回应。
只有她的对白与轻微室内底噪，无画外人声、无配乐、无字幕。
输出中文完整提示词。
```

**你会得到：** 人物定义、摘要、参考保留分析、带时间轴的镜头描述、整体声音和配乐说明。默认只输出一个完整代码块。

> 未指定时长时，技能以 **6 秒作为创作规划默认值**，并在摘要中说明。它不是 H3 平台时长上限；生成前请按所用平台的实际选项设置时长与比例。

## 02 · 怎样给需求，结果更可控

最有帮助的信息是：**发生了什么、人物想要什么、必须说什么、哪些东西不能变。** 不必先学习表演术语，也不必替技能分类所有图片。

```text
使用 $tudou-single-h3。

【片段】时长、画幅、题材、视觉风格。
【人物】谁在场，什么关系，谁想从对方那里得到什么。
【事件】刚发生了什么，什么刺激引起这次变化。
【台词】逐字给出；注明是否必须原样保留。
【表演】情绪起点、转折、结尾，以及克制或外放程度。
【镜头】景别、构图、视线方向，是否允许切镜和身体动作。
【参考图】直接附图；有明确用途时顺便说明。
【声音】对白、环境声、配乐分别允许什么。
【限制】不加人物、不改台词、不哭、不笑等真正重要的要求。
```

不用每次填满。信息不充分时，技能应采用保守表达；只有缺失内容影响核心剧情或硬约束冲突时，才需要澄清。

## 03 · 参考图：人物、场景、风格与构图分开用

图片越多，不一定越稳。关键在于每张图负责什么。

| 图片用途 | 保留什么 | 使用方式 |
| --- | --- | --- |
| 人物卡 / 服装图 | 人物身份、发型、服饰与已有配饰 | 作为人物参考，标记 `fully_preserved` |
| 场景图 | 建筑、环境、空间与已有物件 | 作为场景参考，标记 `fully_preserved` |
| 纯风格图 | 色彩、光线、镜头质感、景深与氛围 | 标记 `attribute_transfer`，不复制其中人物或建筑 |
| 纯构图 / 动作示意 | 左右位置、机位、景别、姿态与动作关系 | 提取成文字约束，不放进最终 H3 参考图上传集合 |
| 指定首帧 | 画面开始时可见的人物、位置、服饰与环境 | 作为片段起始状态，后续变化从它接续 |

**一组实用例子：** 你有角色 A、角色 B、房间，以及一张想模仿站位的电影截图。先把四张图交给编写提示词的助手；如果截图仅用于构图分析，最终传给视频模型的参考图通常只保留角色 A、角色 B 和房间。

截图中的站位转为“人物 A 在画左、人物 B 在画右、相距约一步”等文字。这样可以减少构图截图的人脸、衣服和背景混入目标画面的问题。

> 若某张图同时是唯一的人物来源、场景来源或指定首帧，就不能简单按“纯构图图”排除。以你的真实用途为准。

上传前，核对最终图片顺序与 `<Subject 1>`、`<Subject 2>` 等编号。排除构图分析图后，要按实际上传顺序重新编号。纯文字需求里的 Subject 则表示文字定义的主体，不是假装存在的参考图。

## 04 · 让情绪成为一段表演

### 从人物意图出发

比较下面两种需求：

| 只给情绪标签 | 给出可以表演的过程 |
| --- | --- |
| “先伤心，再生气，最后释然。” | “她想听到解释。对方沉默后，她意识到答案已很清楚，停止追问；说完最后一句，仍有失落，但不再等待。” |
| “他霸气一点。” | “他不抬高音量，始终看着对方；等对方说完，留半秒沉默，再清晰说出原台词。” |
| “两个人吵起来。” | “A 要一个承诺，B 试图回避；A 听到回避的关键词后收紧下颌，下一句从试探转为追问。” |

情绪来自事件对人物目标的影响。写清楚这层关系，声音、眼神和停顿才容易朝同一个方向工作。

### 说话的时候，另一个人也在反应

双人片段应同时考虑：

1. **触发词：** 听者被哪一个真实台词中的词触动。
2. **第一反应：** 先变化的是目光、下颌、呼吸，还是画面中可见的身体部位。
3. **反应时差：** 听完再反应，还是稍迟才意识到含义。
4. **接话选择：** 正常接、快接、打断或迟接，哪一种符合关系与剧情。

这些是按内容选择的手段。不要为了表现“会演戏”，给每句话都加吞咽、喘气、挑眉或眼泪；用户锁定完整台词时，也不要自行改成残句。

### 给台词留足时间

以下是技能采用的 **中文创作估算值**，不是模型参数，也不是所有演员的固定语速：

| 演法 | 参考语速 |
| --- | --- |
| 正常交谈 | 约 4 字 / 秒 |
| 激动、争吵 | 约 5–6 字 / 秒 |
| 克制、沉重、低声 | 约 2.5–3 字 / 秒 |
| 一字一顿的强调 | 约 2–2.5 字 / 秒 |

例如，一句 12 字的克制对白，仅发声通常就需要约 4–4.8 秒，还要给准备、停顿和余波留时间。听者反应若发生在说话过程中，可与对白共用时间；发生在说完之后的反应要单独预留。

如果时长不够，先减少可选动作，再调整未锁定的时间分配。原台词、慢速演法和总时长都必须保留却无法兼容时，需要明确调整其中一项。

## 05 · 读懂六段输出

| 标题 | 你要检查什么 |
| --- | --- |
| `subject_definitions:` | 人物、场景和声音身份是否正确，编号是否一致 |
| `summary:` | 总时长、画幅、剧情节拍和参考图分工是否准确 |
| `retention_analysis:` | 哪些内容完整保留，哪些仅迁移风格；无图时是否明确说明 |
| `detailed_description:` | 全局视觉约束、镜头、连续时间轴、表演与对白是否一致 |
| `overall_soundscape:` | 环境声、声音质感和混音关系是否符合需求 |
| `non_diegetic_music:` | 配乐要求是否正确；不需要时明确写“无配乐” |

对白写在对应时间段下面，人物动作写在 `<d>` 外：

```text
00:01.200–00:04.600：她保持对画面右侧的注视，眉间轻微收紧；口型随实际发音自然变化。
<Subject 1> (S1): <d>[Chinese] <softer>你<pause>真的要走吗？</d>
```

一条完整台词只在时间轴中出现一次。声音总述可以补充音色与音量，但不要再复制整句台词。

`<d>`、`<softer>`、`<pause>` 等是本技能采用的书写约定，不代表每一个 H3 平台都支持同一套解析语法。若你的环境不支持，保留相同表演意图，改为自然语言描述。

<summary><strong>C · 修改已有提示词，只修一个问题</strong></summary>

```text
使用 $tudou-single-h3，修改我下面粘贴的提示词。
目前问题：人物每句话都微笑，听者没有反应，最后两秒台词说不完。
保留原人物、画面风格、台词、总时长和镜头数量。

【在这里粘贴原提示词】
```

</details>

## 08 · 与 TD 画布 / H3 生成流程衔接

先观看顶部的配套视频了解演示流程。下面说明这份 Skill 在制作中的位置；具体入口与可用模型选项以你使用的 TD 画布版本为准。

```mermaid
flowchart LR
    A[剧情与原始台词] --> C[Skill 编排提示词]
    B[人物 / 场景 / 风格参考] --> C
    C --> D[核对六段输出与图片顺序]
    D --> E[填入 TD 画布或 H3 生成环境]
    E --> F[按平台选项设置并生成]
    F --> G[检查表演并针对问题修改]
    G --> C
```

1. **准备输入。** 提供剧情与不可修改的台词；需要参考图时，准备人物、场景或首帧素材。
2. **编写提示词。** 在能读取技能文件的助手中调用 `tudou-single-h3`，得到完整六段内容。
3. **核对素材。** 按最终 Subject 顺序放入参考图。只用于构图分析的截图不传入最终生成环境。
4. **配置生成。** 将代码块中的提示词正文填入相应输入位置，不必复制外层三个反引号；核对实际支持的时长、画幅与生成模式。
5. **回看表演。** 优先看台词是否说完、听者是否有反应、口型是否同步、结尾情绪是否保留。
6. **聚焦修改。** 把具体偏差反馈给助手，例如“‘早就’之后没有反应”“道歉太快”“结尾突然微笑”，再生成一份完整替换稿。

“开源 + 闭源结合”是顶部视频的主题；这份技能提供可阅读的编排规则，不附带模型权重、平台账号、API Key 或生成服务。

## 09 · 常见问题

<details>
<summary><strong>一定要有参考图吗？</strong></summary>

不需要。纯文字可以直接使用。此时主体来自文字描述，参考分析应明确写出“未提供参考图”。

</details>

<details>
<summary><strong>只能写文戏、只能写真人吗？</strong></summary>

不限定题材或视觉风格。文戏是本版重点增强的能力；动作片段可以用动作准备、接触、重心转移和后续运动组织时间轴。风格由你的输入决定。

</details>

<details>
<summary><strong>为什么中文需求输出了英文标题？</strong></summary>

六个英文标题是固定结构，便于稳定复制和复用。标题下面的描述默认跟随请求语言，中文需求通常用中文；原始台词保持你给出的语言与文字。

</details>

<details>
<summary><strong>没有对白、没有音乐，还要六段吗？</strong></summary>

要。无对白时不用创建对白块；声音与配乐段可以明确写“无对白”“无配乐”或对应的静音要求，不能直接删掉标题。“无配乐”不等于禁止环境声或人声。

</details>

<details>
<summary><strong>为什么没有自动加 Facial Realism？</strong></summary>

该词只在已确认加载对应 `MiniMax-H3-Facial-Realism-CloseUp` LoRA 时使用。技能不会假定它已加载，也不把它当作通用画质增强词。

</details>

<details>
<summary><strong>能一次完成整部短片吗？</strong></summary>

默认交付单位是一个片段。多段创作时，可以逐段调用，并给下一段提供前一段的结束状态：视线、身体朝向、情绪强度、呼吸与声音残留。不要让新片段无缘无故从中性状态重新开始。

</details>

<details>
<summary><strong>安装后没有识别到怎么办？</strong></summary>

确认实际路径是 `skills/tudou-single-h3/SKILL.md`，没有多套一层解压目录；检查入口文件名、技能名称和参考文档是否完整。如果使用自定义技能目录，按当前客户端配置放置，并重新打开对话后检查。

</details>
